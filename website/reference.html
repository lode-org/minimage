C ABI (minimage_*)

Function symbols use the minimage_ prefix. Every buffer is caller-owned. Coordinates, lattice vectors, and origins share one consistent length unit; minimage_cell_from_con_box takes angles in degrees. Displacements compute wrap(q - p).

Every int-returning function in the first table returns 0 on success and 1 on failure (null pointer, invalid cell, buffer/index mismatch, or overflow). Read minimage_last_error() on the same thread immediately after a nonzero return; do not free the returned pointer. The next successful minimage_* call on that thread clears the slot so minimage_last_error() returns NULL. minimage_version() returns a process-static string and neither reads nor modifies the error slot.

Loading at run time

A host that opens the shared library by path, rather than linking it, resolves three symbols by name and takes every other operation from a table. These calls are additive: the entry points above keep their names, signatures, and 0 / 1 returns.

  1. minimage_abi_stamp(&abi) writes the ABI the library was built for.
  2. minimage_abi_compatible(&host) returns MINIMAGE_STATUS_OK when the library serves a host compiled against host: the same MINIMAGE_ABI_MAJOR and the same MINIMAGE_ABI_LAYOUT_REVISION. The minor is informational and is not compared.
  3. minimage_ops_get(&ops) fills the operations table. A null member is an operation the library lacks.

Every int32_t this layer returns is a status: 0 is success, a positive code is a failure the caller can recover from, and a negative code is a misuse of the interface or a fault inside the library. Branch on the code. minimage_last_error() is text for a person, valid until the next minimage_* call on the same thread, and its wording is not stable. A panic inside the library is caught at the boundary and returned as MINIMAGE_STATUS_PANIC.

MINIMAGE_STATUS_ERROR 1 Any failure of the entry points that predate this layer; never returned by the table

MINIMAGE_STATUS_UNSUPPORTED 3 The matching capability is zero; nothing was written
MINIMAGE_STATUS_INCOMPATIBLE 4 Another major version or layout revision
MINIMAGE_STATUS_NULL_POINTER -1 A required pointer is null
MINIMAGE_STATUS_BAD_SIZE -2 A struct's size is smaller than the size member
MINIMAGE_STATUS_BAD_COUNT -3 A row count whose buffer would not fit in the address space
MINIMAGE_STATUS_BAD_OVERLAP -4 The output overlaps an input without being that input
MINIMAGE_STATUS_PANIC -5 A fault inside the library, caught at the boundary
Kind Type Layout
frozen minimage_abi Three uint32_t: major, minor, layout revision. Written through a pointer
growable minimage_caps uint32_t size, then one uint32_t flag per capability
growable minimage_ops uint32_t size, uint32_t reserved, then function pointers
growable minimage_lattice_info uint32_t size, flags, then the stored vectors, origin, and widths
opaque minimage_lattice Incomplete type; only pointers cross the boundary

A growable struct starts with uint32_t size. The host sets it to sizeof as it compiled the struct. The library zeroes that many bytes, writes the whole members that fit, and sets size to the bytes it wrote, so a member the host knows and the library does not reads as zero, and a byte past the host's size is never touched. Members only ever append. minimage_caps and minimage_ops are outside the frozen layout revision; a new capability or operation is a new member at the end and a new minor.

A lattice is immutable once built, so any number of threads may read one handle at once; minimage_lattice_free must not run while another thread uses it. An orthorhombic lattice stores each periodic vector with a positive diagonal entry, whatever sign it was built with: the edge -L spans the lattice the edge +L spans. A sheared lattice keeps the vectors it was given. The engine wrap of a sheared lattice with an open axis is not provided (minimage_caps.wrap_open_sheared is 0): the wrap calls return MINIMAGE_STATUS_UNSUPPORTED and the nearest-image calls serve it. A call with n = 0= reads no buffer.

The C11 test tests/c/abi_host.c pins the frozen layouts with _Static_assert on sizeof and offsetof, and loads the library with dlopen.

A slab rounds its in-plane coordinates and tries the nine neighbouring images on a Lagrange-reduced basis of its two vectors; a wire rounds along its one. The component normal to the periodic vectors is kept. A half-box tie keeps the engine wrap s - floor(s + 1/2), as Cell::displacement_euclidean does. With all three axes periodic a PartialCell is a Cell and returns its displacement bit for bit.

wrap_ortho_half_strict(delta, length) (Rust) and minimage::wrap_ortho_half_strict(delta, length) (C++) give identical results. The result is delta - n * length for an integer n, folded from the exact remainder fmod(delta, length) into the closed interval [-length/2, length/2], so it is finite and in range for any finite delta and finite positive length, including large multiples such as 1e308 against 0.5. When the remainder equals length/2 exactly in binary the result keeps the sign of delta: 15 and -15 against 10 give 5 and -5. A decimal tie such as 0.45 against 0.3 is not a binary tie and returns its nearest image, -0.14999999999999997. A non-finite delta, or a length that is not finite or not strictly positive, returns NaN; Rust does not panic and the C++ function stays noexcept.

MINIMAGE_SIMD overrides the SIMD path choice. An unknown name is ignored. A name this CPU cannot run selects scalar. The selection is cached. Details are on SIMD paths and dispatch.
